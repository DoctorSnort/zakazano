# Заказано

Личный справочник по заведениям и тому, что в них заказывали.

Ходишь по кафе, пробуешь блюда, а через полгода возвращаешься и не помнишь ни что брал,
ни было ли это вкусно. Приложение это и закрывает: заведение → блюда и напитки → оценка,
цена, комментарий, фотографии.

Всё хранится на телефоне. Сеть нужна ровно для одного — сложить резервную копию
в ваш собственный Google Диск, и то по желанию.

## Что умеет

- Список заведений с поиском по названию и адресу, сортировкой по алфавиту, оценке и свежести.
- **Биомы** — независимые наборы заведений: «Стандартный» для дома, «Тайланд» для поездки.
  Переключаются в заголовке главного экрана, открывается всегда последний выбранный.
  Пока биом один, экран выглядит как раньше.
- Долгое нажатие по заведению в списке — редактировать, перенести в другой биом или удалить,
  не заходя внутрь.
- На карточке заведения — средний балл по пятибалльной шкале: **стрём = 2, никак = 3,
  неплохо = 4, кайф = 5**. Считается по всем блюдам и напиткам сразу, с двумя знаками
  после запятой. Своя оценка месту в него не входит — это именно «как тут кормят».
- Внутри заведения — вкладки **Блюда** и **Напитки**, листаются свайпом.
- У напитков необязательный вид: коктейль, пиво, настойка. В списке он идёт после
  названия курсивом, а фильтр по нему живёт в верхней панели — чтобы не отнимать
  высоту у самого списка.
- Оценка из четырёх ступеней: **стрём · никак · неплохо · кайф**. Никаких звёздочек —
  оценивать нужно за секунду, не задумываясь «это 7 или 8 из 10».
- Фильтр по оценкам (можно выбрать несколько), цена, комментарий.
- Фотографии с камеры или из галереи, просмотр во весь экран. У заведения своя
  фотография, её видно прямо в списке — там же выводится и заметка.
- Своя оценка заведению — отдельно от средней по блюдам.
- Резервная копия всех данных в один ZIP-файл и восстановление из него.
- Та же копия может уезжать в **Google Диск** — вручную или сама раз в сутки.
  Подробности и настройка — в [GOOGLE-DRIVE.md](GOOGLE-DRIVE.md).
- Светлая и тёмная тема, при желании — цвета из обоев системы (Material You).
- Коты вместо абстрактных пиктограмм: своя мордочка на каждую оценку, кот над пустой
  миской там, где ещё ничего не записано, спящий кот там, где фильтр ничего не нашёл.
  Рисунки построены на иконке `cat` из Tabler Icons (MIT) — см. [THIRD-PARTY.md](THIRD-PARTY.md).
- Внутри заведения в шапке только его название — крупно и с зелёным свечением.
  Адрес, заметка и своя оценка живут в редакторе: в списке блюд они лишь отвлекали.

## Разрешения

Приложение не запрашивает у пользователя ни одного разрешения. Фотографировать помогает
системная камера, выбирать снимки — системный Photo Picker: в обоих случаях файл отдаёт
система, а доступ ко всей памяти или к камере приложению не нужен.

В манифесте объявлены только `INTERNET` и `ACCESS_NETWORK_STATE` — они нужны для выгрузки
на Диск и выдаются без спроса. Там же лежит блок `<queries>` с `IMAGE_CAPTURE`: с Android 11
приложение не видит чужие пакеты, и без этой строчки проверка «есть ли на телефоне камера»
отвечает «нет» даже там, где камера есть.

## Сборка

Нужны JDK 21 (подойдёт тот, что внутри Android Studio) и Android SDK с платформой 37.2.

```bash
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
./gradlew assembleDebug
```

Установка на подключённый по USB телефон:

```bash
./gradlew installDebug
```

Тесты:

```bash
./gradlew testDebugUnitTest          # логика: цены, сортировка, фильтры
./gradlew connectedDebugAndroidTest  # база данных, нужен телефон или эмулятор
```

`local.properties` с путём к SDK машинозависим и в git не попадает —
Android Studio создаст его сама при первом открытии проекта.

## Как устроено

```
model/            Доменные типы: Rating, ItemKind, Venue, Item
data/db/          Room: сущности, DAO, база
data/repo/        Репозитории и преобразование сущностей в доменные модели
data/photo/       Хранение, сжатие и уборка файлов фотографий
data/backup/      Сборка и разбор ZIP-копии
data/sync/        Google Диск: доступ, запросы к API, ежесуточная выгрузка
data/prefs/       Настройки в DataStore
util/             Форматирование цены, сортировка с учётом русского алфавита
ui/               Экраны (Screen + ViewModel на каждый), тема, общие компоненты
di/               AppContainer — зависимости собираются руками, без Hilt
```

Пара решений, которые стоит знать, прежде чем что-то менять:

- **Оценка хранится числом** (`ratingCode` 0–3), а не строкой: по этой колонке SQL считает
  среднюю оценку заведения одним запросом. Значения кодов менять нельзя — поедут
  сохранённые записи.
- **Сортировка по алфавиту делается в Kotlin**, а не в SQL. `COLLATE NOCASE` в SQLite
  работает только с латиницей: на кириллице «Ёлки» и «ёлки» разъезжаются, а «Ё» уезжает
  в конец алфавита. Правильный порядок даёт `java.text.Collator` для русской локали.
- **Цена хранится в копейках** целым числом. В `Double` 0.1 + 0.2 не равно 0.3,
  и на суммах это однажды вылезет.
- **Файлы фотографий база не удаляет.** Каскад сносит строки, но про файлы знает только
  приложение — их подбирает `PhotoCleaner` после каждого удаления и при запуске.
  Он смотрит в два места: таблицу `photos` и колонку `venues.photoFileName`. Забыть
  про второе — значит удалить фотографии заведений при первой же уборке.
- **Google Диск — это резервная копия, а не двусторонняя синхронизация.** В Диск уезжает
  один файл `zakazano-backup.zip` — тот же самый архив, что и у ручного экспорта, и
  перезаписывается он на месте. Восстановление заменяет данные целиком. Область доступа
  одна — `drive.file`: приложение видит на Диске только то, что само туда положило,
  и Google не требует за неё платной проверки приложения.
- **Ключей Google в репозитории нет и быть не должно.** Android-клиент OAuth опознаётся
  по имени пакета и SHA-1 подписи, поэтому после смены ключа подписи нужно добавить
  новый отпечаток в Google Cloud — см. [GOOGLE-DRIVE.md](GOOGLE-DRIVE.md).
- **Биом — владелец заведения.** `venues.biomeId` ссылается на `biomes` с каскадным удалением,
  так что удаление биома уносит его заведения, позиции и строки фотографий. Последний биом
  удалить нельзя. Миграция 2 → 3 складывает всё, что было до биомов, в «Стандартный» (id = 1).
  Копии без биомов (версии 1.x–2.0) при восстановлении тоже попадают в «Стандартный».
- **Схема базы версионируется миграциями** (`data/db/Migrations.kt`), без пересоздания:
  у приложения есть живой пользователь с записями. На каждую миграцию есть тест
  в `MigrationTest`, который проверяет, что старые записи доезжают целыми.
